# 12月の投稿カレンダーと各ジャンルの型(2026/11/24 作成)

12月から、XとnoteでAI企業の相関図のデータを使った投稿を毎日続けるための計画です。
**1日1ジャンル、1ジャンル1本。** この文書は「何曜日に何を出すか」と「1本の作り方(型)」を決めるもので、実際の投稿はしません(投稿は祐真さん本人が行う)。

## 0. 投稿の方針(2026/11/24に改めた。いちばん大事)
**ニュースの要約は作らない。「相関図の線をたどって、初めて分かること」を書く。** だれでも知っている事実だけの投稿は価値がない(祐真さんの指摘)。
- 材料は「人」と「線」: 経歴・入社の経緯・どの会社をどう渡り歩いたか・だれとだれがつながっているか・他の人が気づきにくい共通点(同じ前職、同じ投資家、同じ親会社、買い手が取引先でもある、など)
- ニュースを使うときも、相関図のデータで「前後の文脈・つながり」を必ず1つ足す。足せない(=広く知られた事実だけ)ときは、その話は使わない
- 人物を主役にする回を増やす。ジャンルが「お金」「提携」「人事」でも、**人または会社の線を1本たどる**書き方にする
- 線のたどり方: 相関図で人・会社を開く → 出身・移籍・出資・取引の線 → その線の出典(`DS`)を開いて確かめる → 「会社名だけ見ると別々なのに、線でつなぐと1本になる」ところを見つける
- 確かめられた事実だけ書く。**経歴の年・肩書き・学歴は、本人・公式・開示で確かめたものだけ**。食い違うものは「春」「資料により異なる」とぼかすか、書かない。なぜ移ったか(理由)は公表されたものだけ
- 投稿の前の自己チェック: 「この文は、相関図を見なくても書ける内容か?」→ そうなら書き直す

## 1. 基本のルール(全ジャンル共通)
- 出典のURLを必ず付ける。出典のない話は投稿しない(うわさは入れない)
- 確かさの印を、本文のどこかに必ず1つ書く(下の「確かさの書き方」)
- 画像は転載しない。顔写真・記事の画像・SNSの画像は使わない。リンクと文章での説明だけ
- 数字が報道ベース・契約の上限・推定のときは、そう書く
- 私生活の詮索はしない。公に発表された仕事の動きだけ
- お金の話は「事実の紹介」だけ。株の売買をすすめる書き方はしない(「買い」「上がる」など)
- 品質チェックで保留になったもの(`inbox/quality/hold-日付.md`)は使わない
- 投稿の前に、出典ページを自分の目で一度開く(inbox の候補は機械が集めたもの)

## 5. 確かさの書き方(Xもnoteも共通)
本文の最後(Xなら出典の前)に、次の言い方を1つ付けます。

| 印 | どんなとき | 書き方の例 |
|---|---|---|
| 公式 | 会社の発表・プレスリリース | 「(公式発表)」 |
| 開示 | 法定の書類(SEC・TDnet・HKEX・決算資料) | 「(適時開示で確認)」「(SEC提出書類で確認)」 |
| 本人 | 本人のXなどの投稿 | 「(本人の投稿)」 |
| 報道 | 報道だけ | 「(報道ベース)」 |
| 推定 | 自分や他社の推定・試算の数字 | 「(推定。公式な数字ではありません)」 |

- データの `confidence`(inboxの項目)や `cf`(おもしろ情報)をそのまま使う。「本人の発言」は「本人」と書く
- 報道ベースの金額は「約」「報道では」を付け、契約の上限は「上限」と書く

## 6. 型(X用の短い型 + note用の長めの型)
**Xの目安:** 日本語は全角100〜130字くらい+出典URL1本。出典が2つあるときは返信(2つ目の投稿)に付ける。
**noteの目安:** 600〜1200字。見出し1+本文+「出典」の一覧+「相関図の見かた」1行+末尾の定型文。
**noteの末尾の定型文**(`newsletter-preview/2026-11-23_note.md` と同じ形):
> この記事は、AI企業の人・出資・取引のつながりを集めた「AI企業の相関図」のデータから書いています。相関図: (公開URL)
> ※ 各項目の確かさは本文の印のとおりです。出典のリンクから元の記事をご確認ください。(発行日 ○○)

### 6-1. 人材の移籍(月)
- **材料:** `inbox/moves/` の最新ファイルの `items`(`name_ja` / `from` / `to` / `role` / `date` / `src` / `confidence`)。本人のXが `src` の先頭にあれば「本人」
- **X:** 「【移籍】○○さん(前職の役職)が△△から□□へ。(役割)。(ひとこと:なぜ注目か)(確かさ)出典URL」
- **note:** 見出し=「○○さんが△△から□□へ」/ ①何があったか ②経歴(前の会社でのこと) ③この会社間の人の往復(画面「人材の流れ」で2社を選ぶと出る数字) ④出典
- **選び方:** `date` が新しいもの優先。さかのぼり(`backfill:true`)は、ネタが無い日の予備にする
- **線を足す:** 移った人の「前の会社」での役割・その会社の仲間(同じ時期に移った人)・移った先と前の会社の取引や出資の線を、画面「人材の流れ」と本体の図で探して1つ足す

### 6-2. 役員人事(火)
- **材料:** `site/data/exectl.js` の `ev`(会社ごとの年表)、`inbox/ir/日付.json` の人事(日本・香港)、`inbox/moves/日付-jp-hr.json`
- **X:** 「【人事】□□社で○○氏が(役職)に就任/退任。(発表日)。(前任者や理由が出典にあれば一言)(確かさ)出典URL」
- **note:** 見出し=「□□社の経営陣、何が変わったか」/ 年表(日付順に3〜5件)+それぞれの出典。上場準備の書類の前後の動きなど、年表の並びを見せる
- **注意:** 理由は出典に書いてあることだけ。憶測の理由は書かない

### 6-3. お金の動き(水)
- **材料:** `inbox/money/日付.json`、index.html の `DEALS`(計算資源の取引)、出資の一覧(`invest.js`)
- **X:** 「【お金】○○が△△に(金額・約)出資/契約。(目的)。(報道ベース/公式)出典URL」
- **note:** 見出し=「○○と△△のお金のつながり」/ ①発表内容 ②金額の中身(上限・段階払いなど出典のとおり) ③相関図で見ると(2社の線を画面で確認) ④出典
- **注意:** 金額は出典の表記のまま。円・ドルの換算は「(参考換算)」と書き、為替の日付を書く

### 6-4. 資金調達(木)
- **材料:** `inbox/vc/日付.json`(`fund` / `gp` / `size` / `startup` / `date` / `src`)、`inbox/money/日付-jp-fund.json`
- **X:** 「【調達】○○が(ラウンド)で(金額)を調達。主な出資者:△△、□□。(何に使うか)(確かさ)出典URL」
- **note:** 見出し=「○○の資金調達」/ ①金額と出資者 ②ほかの出資先(相関図の「出資の一覧」で出資者を選ぶ) ③出典
- **注意:** 評価額は報道ベースが多い。公式なら「公式」と書く。「ファンドの最終クローズ」と「投資先への出資」を混ぜない

### 6-5. 提携・協業(金)
- **材料:** `inbox/money/日付-jp.json`(日本の提携係)、`inbox/money/日付.json`
- **X:** 「【提携】○○と△△が(分野)で提携。(何をするか1行)。(公式発表/報道)出典URL」
- **note:** 見出し=「○○と△△、何を一緒にやるのか」/ ①発表の中身 ②両社のこれまでのつながり(相関図の「共通のつながり」) ③まだ分からないこと ④出典
- **注意:** 「導入を検討」と「契約した」を区別する。発表の言葉のとおりに書く

### 6-6. 買収・出資(水・第2週)
- **材料:** `inbox/ir/日付.json`(`cat` が買収・出資など)、`inbox/money/日付-ir.json`、`inbox/disclosures/日付.json`
- **X:** 「【買収】○○が△△を(取得割合・金額)で買収/出資。(適時開示で確認)出典URL(開示のPDF)」
- **note:** 見出し=「○○が△△を買収」/ ①開示の要点(日付・割合・金額) ②背景(出典にあるものだけ) ③用語の説明(TDnet・HKEXとは何か、1〜2行) ④出典
- **注意:** 開示PDFのURLを出典にする。PDFの文章を長く引用しない(要点を自分の言葉で)

### 6-7. 計算資源・電力(水・第4週)
- **材料:** `inbox/money/日付-dc.json`、`docs/compute_deals_2026-11.html`、`DEALS`
- **X:** 「【計算資源】○○が△△とGPU/電力/データセンターの契約。(規模:MW・金額)(上限/報道ベースの別)出典URL」
- **note:** 見出し=「AIの電力とチップ、だれがだれと契約したか」/ 契約の表(1枚資料の形をそのまま使う)+読み方+出典
- **注意:** 契約の「上限」と「実際に使う量」を混ぜない

### 6-8. 採用の動き(火・第2・第4週)
- **材料:** `inbox/moves/日付-hiring.json`
- **X:** 「【採用】○○社が(人事責任者/新部門)を新設・就任。公式の採用ページで(職種数)(日付時点)(確かさ)出典URL」
- **note:** 見出し=「○○社は何の人を増やしているか」/ 公式の採用ページで確かめた数と日付 + 前回との差(確かめられた分だけ)
- **注意:** 増減は「公式ページで確かめた数」だけ。推測しない

### 6-9. この人の経歴(土。ほかの曜日でも、人物の回は大歓迎)
- **見本:** `posts/drafts/2026-12-01.md`(ローレン・タン氏。Netflix→Meta→Cursor→SpaceXSI。本人のプロフィール・公式・開示で確かめた線だけで書いた)
- **材料:** 本体の人物カード(相関図で人物を開く)、`inbox/deep/日付.json`、「幹部の年表」
- **X(連投2〜3本):** 1本目「【この人】○○氏の経歴を3行で」/ 2本目 年表3点 / 3本目 出典と確かさ
- **note:** 見出し=「○○氏はどこから来て、いまどこにいるか」/ 年表(年・会社・役割)+人のつながり(相関図で見える線)+出典
- **注意:** 顔写真は使わない(ライセンスの確認ができたものだけ本体では使うが、投稿では転載しない)。学歴・職歴は出典のあるものだけ。家族・住所など私生活は書かない

### 6-10. おもしろ情報(日)
- **材料:** `inbox/fun/日付.json` の `items`(`cat` / `p` / `t` / `note` / `cf` / `chk` / `src`)
- **X:** 「【おもしろ】○○氏の(愛用品/愛読書/社名の由来…):△△。(確かさ)出典URL」
- **note:** 見出し=「○○氏の△△」/ 本文+「出典のページで確かめた(chk=o)」か「検索で確かめただけ(chk=s)」かを明記+出典
- **注意:** `chk=s`(出典のページを開いて確かめていないもの)は「報道では」と書き、断定しない。名言は原文を一字一句ページで確かめたものだけ。装い・ブランドは画像を載せず、出典へのリンクと文章だけ

## 7. 1日の作業の流れ(目安15〜20分)
1. `git pull`(毎朝の調査が足した最新を取る)
2. 今日のジャンルを見て、上の「材料」のファイルを開く
3. 候補を1つ選ぶ(確かさが「公式」「開示」「本人」のものを優先)
4. 出典ページを開いて、日付・名前・金額を目で確かめる
5. 型に当てはめて下書き(Claudeに「今日の○○の投稿を作って」と頼めば下書きは作れる)
6. 確かさの印と出典URLがあるか、画像を使っていないかを確認して投稿

## 8. TDnetとHKEXとは(用語メモ)
- **TDnet(ティーディーネット)**: 東京証券取引所に上場している会社が、投資家に知らせるべきことを発表する公式の仕組み。決算・出資・買収・役員の交代などが、PDFで出る。「適時開示」と呼ぶ
- **HKEX(エイチケーイーエックス)**: 香港取引所。香港に上場している会社が、同じように発表する場所
- 相関図では `scripts/ir_watch.py` が毎朝この2つの新着を見て、相関図にある会社の出資・買収・役員人事だけを拾い、PDFを開いて確かめたものを `inbox/ir/` に足しています(シンガポールのSGXは取引所側が自動取得を断るため今は読めない)。確かさの印は「開示」になる
