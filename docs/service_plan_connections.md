# 「接点探し」を有料サービスにする案(2026年11月18日)

相関図の「2社の共通のつながり」(`site/data/common.js`)を使って、
**「この会社に、誰を通せば・どの話題で入れるか」を調べて渡す**サービスの案。
前の検討(`docs/business_notes.md` の1章「B2Bで受託・有料化」)の続き。

> 注意: 競合の値段は公開情報からの目安で、契約前に必ず確かめる。この案の数字(値段・件数)はすべて仮置き。

---

## 1. ひとことで言うと
- 売るのは「データ」ではなく **「入り口の地図」と、それを使った一言の提案**
- 例: 「A社に会いたい」→「A社とB社(自社の取引先)は、同じVCから出資を受けている。そのVCのパートナーXさん経由が近い。話題は、A社が先月発表したGPU契約」
- Crunchbase や SPEEDA は「調べる道具」。こちらは「調べた結果を、営業が明日使える形にして渡す」ところで差をつける

## 2. お客さん(おすすめ順)
| 順 | お客さん | 困りごと | 払う理由 |
|---|---|---|---|
| ① | **日本企業の新規事業・提携担当**(大手〜中堅) | AI企業と組みたいが、どこから入ればいいかわからない | 1件つながれば大きい。社内の稟議資料にも使える |
| ② | **AIの法人営業チーム**(SaaS・SIer・データセンター・電力) | 大手の誰に当たるべきか、つながりが見えない | 商談1件の価値が高い |
| ③ | **ヘッドハンター・人材紹介** | AI人材の移籍とつながりを早く知りたい | 前の検討でも上位。移籍アラートと相性がよい |
| ④ | **M&Aアドバイザー・VC** | 買い手・投資先の候補と、その間の人を知りたい | 道具は既に持っているので、日本語の図解と速さで勝負 |
| ⑤ | **スポーツクラブ・自治体**(熊本など) | スポンサー・誘致先の企業に入るきっかけがない | 自分の現場(ヴォルターズ)で試せる |

**最初に狙うのは①と⑤。** ①は払える額が大きく、⑤は自分で使って実績を作れる。④はすでに高い道具を持っているので後回し。

## 3. 売るもの(3段)と値段の仮置き
| 商品 | 中身 | 値段(仮) | 手間 |
|---|---|---|---|
| A. **接点レポート(1社1枚)** | 指定した営業先1社について、共通の出資者・人物・取引先・使っているAI、最短ルート、最近の動き、話のきっかけ3つ。出典つき | 1件 3〜5万円 | 半自動。最後に人が確かめる |
| B. **月額の見張り** | 指定した10〜30社の人事・出資・取引の変化を週1でまとめて届ける。「今週、会いに行く理由ができた会社」を上に出す | 月 5〜15万円 | ほぼ自動(毎朝の更新の仕組みを使い回す) |
| C. **紹介・同行(成果報酬)** | 実際にキーパーソンにつなぐ、または一緒に会いに行く | 着手金+成功時に別途 | 人の力が要る。数は絞る |

- 入り口は **A(単発)** にして、気に入った会社を **B(月額)** に上げる
- **C は慎重に。** 人の紹介は信用が命なので、自分が本当につなげる範囲だけにする(下のリスク参照)
- 業界版(スポーツ、熊本×台湾など)は、同じ仕組みで「カスタム相関図の受託」として別に受ける

## 4. 競合とのちがい
| 相手 | 何が強いか | こちらの立ち位置 |
|---|---|---|
| Crunchbase / PitchBook | 世界の資金調達データが多い。英語 | 日本語、図で見せる、「日本の会社から見たつながり」 |
| SPEEDA / INITIAL(ユーザベース) | 日本の業界・スタートアップ情報が厚い。大企業に導入されている | 道具ではなく「1社1枚の提案」まで作って渡す。小さく買える |
| Sansan | 社内の名刺から「誰が誰を知っているか」がわかる | 外の公開情報の線。Sansanと**組み合わせて使える**(外の線+社内の名刺) |
| LinkedIn Sales Navigator | 人のつながりが見える | 会社どうしの出資・取引・AI利用の線まで一緒に見える |
| 調査会社・コンサルの受託 | 深く調べる | 安く・速く・毎週更新 |

**勝てるところ:** 日本語/時間の流れが見える/毎日更新している/AIと半導体・電力までつながっている/熊本・台湾の土地勘。
**勝てないところ:** データの量と網羅性。ここで張り合わない。

## 5. 最初の一歩(MVP)— 4週間
1. **1週目: 見本を3枚作る**
   - 「共通のつながり」の結果を、1社1枚のレポートにする(中身は3章のA)
   - 題材は、実際に声をかけたい相手を選ぶ(例: ヴォルターズのスポンサー候補1社、熊本に来ている半導体関連1社、知り合いの会社が組みたいAI企業1社)
2. **2週目: 自分で使ってみる**
   - ヴォルターズのスポンサー営業で1枚使い、話が進んだかを記録する(⑤の実績づくり)
3. **3週目: 3〜5人に見せる**
   - 新規事業担当・人材紹介・営業の知り合いに見本を見せて、「いくらなら払う?」「何が足りない?」を聞く
4. **4週目: 決める**
   - 3人以上が「払う」と言えば、Aを有料で受け始める(最初の数件はお試し価格で)。言われなければ、足りないと言われた点を直すか、発信の武器(前の検討の1番)に戻す

**この間に作るもの(リポジトリ側)**
- 共通のつながりの結果を「1枚の資料」として書き出す機能(印刷・PDFにできる形)
- 営業先の一覧を入れると、毎週の変化をまとめる仕組み(Bの元)
- 線ごとの「確かさの印」(公式発表/報道ベース/推定)。売り物にするなら必須

## 6. リスクと対策
| リスク | 何が問題か | 対策 |
|---|---|---|
| **個人情報の法律**(個人情報保護法) | 公開されている役員の名前や経歴でも、一覧にして調べられる形にすると「個人情報データベース」になる。それを**お客さんに渡すのは「第三者提供」**にあたり、本人の同意か、国への届け出(オプトアウト)などが要る | 最初は「会社どうしの線」と「会社が公式に発表した役職」までにする。個人の一覧そのものは売らず、レポートの中で必要な人だけ触れる。**有料化の前に弁護士に一度確認する** |
| **紹介の仕事の決まり** | 転職のための人の紹介でお金をもらうと「有料職業紹介」の許可が要る。M&Aの仲介にも国のガイドラインがある | 人材向け(③)はアラートと情報提供までにして、紹介そのものは許可のある会社と組む。M&Aは情報提供だけ |
| **写真の権利** | 実名の人の写真は、肖像と著作権の両方に注意。売り物に使うと責任が重くなる | 有料のレポートには**顔写真を使わない**(名前と役職だけ)。サイト側も、権利を確かめた写真だけにする今のルールを続ける |
| **データのまちがい** | 古い・まちがった線で営業すると、お客さんの信用を傷つける | 全部の線に出典と日付。報道ベースには印。レポートは最後に人が確かめる。「判断の材料であり、保証ではない」と契約に書く |
| **実名の人についての書き方** | 悪く書くと名誉の問題になる | 事実と出典だけ書く。評価や推測は書かない(今のルールのまま) |
| **データの元の決まり** | 他のサイトのデータを使うとき、規約で商用利用を禁じていることがある | 公式発表・有価証券報告書・報道へのリンクを元にする。他社データベースの中身は写さない |
| **自分の時間** | 本業(ヴォルターズ)と両立できるか | A・Bはほぼ自動に。Cは月に数件まで |

## 7. 数字の見通し(仮)
- 最初の半年: Aを月3〜5件+Bを2〜3社 → 月20〜50万円程度
- Bが10社になれば月50〜150万円。ここで初めて「事業」と呼べる
- 費用: ほぼ自分の時間とAIの利用料。サイトの公開先(自分のドメイン)は有料化のときに用意する

## 8. 決めること(持ち主が判断)
1. 最初のお客さんを ①新規事業担当 と ⑤スポーツ・自治体 のどちらから始めるか(おすすめ: ⑤で実績→①に売る)
2. 個人名をどこまで載せるか(おすすめ: 有料版は会社の線と公式の役職まで)
3. 自分の名前で売るか、ヴォルターズの新規事業として出すか
