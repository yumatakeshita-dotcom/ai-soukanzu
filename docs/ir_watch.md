# 決算資料・適時開示(IR)ウォッチ(2026/11/21追加)

`python3 scripts/ir_watch.py` が、日本(TDnet)・香港(HKEX)・シンガポール(SGX)の新着開示から、
相関図にある会社の「出資・買収・役員人事」の提出書類を拾い、PDFを実際に開いて確かめます。足すだけで、消しません。

## 見る会社
- 日本: `site/data/jpco.js`(相関図の上場企業)のコードを自動で読む
- 追加: `inbox/ir/targets_extra.txt`(市場<TAB>コード<TAB>会社名。JP・HK・SG)。足すだけ

## 取引所ごとの状況(2026/11/21)
| 取引所 | 状況 |
|---|---|
| TDnet | 読める。直近3営業日(`--days`で変更)の一覧を全ページ見る |
| HKEX | 読める。英語版の最新の一覧(約1日ぶん)を毎朝見る |
| SGX | **読めない**。2026/11/21に `api.sgx.com` の環境の許可は通ったが、SGX側のサイト(Akamai)が自動の取得を「Access Denied」で断る。回り道はしない。`links.sgx.com` は別のページ(IPO用)で開示のデータではなかった。SGXの開示を読むには、SGXの公式の提供方法(データ提供・API契約など)を調べる必要がある |
| 韓国DART・EDINET | 今は読めないので対象外 |

## 確かめ(全部通ったものだけ保存)
1. PDFが開けて本文が取れる 2. 本文に会社のコード(か名前)がある 3. 本文の日付が一覧の日付の前後7日 4. 本文にも表題と同じ種類の言葉がある 5. (自動で相関図に足すもの)相手の名前が本文にもある
落ちたものは `inbox/ir/日付.json` の `rejected` に理由つきで残る。

## 保存先
- `inbox/ir/日付.json` 確かめを通った開示の記録(種類は 買収・出資・役員人事・売却・異動)。`import` の欄で、相関図への足し方がわかる
- `inbox/money/日付-ir.json` 買収・出資のうち、**表題から買った側と相手が確実にとれ、相手の名前が本文でも確かめられたもの**だけ自動で足す(確かさ=開示)。毎朝の `merge_inbox.py` が「調査の新着」と相関図に出す
- 役員人事は、人の名前の取り違えを避けるため自動では `inbox/moves/` に足さない。記録(`inbox/ir/`)にある `import` が「記録のみ」のものを、毎朝の引き抜き調査が本文を読んで名前・役職を確かめてから `inbox/moves/日付-ir.json` に足す(出典は開示のPDF、確かさ=開示)
- `inbox/ir/status.json` 取引所ごとの取得結果(読めなかった理由が入る)。`seen.txt` は見たものの目録

## 毎朝の使い方
引き抜き調査 v5(毎朝7:29、定期タスク「調査: 引き抜き(人の移籍) v5(適時開示IRつき)」)の最初に `python3 scripts/ir_watch.py` を動かす。v4(7:26)は止めた(消していない)。手順の文は `project-files/money-research/moves_v5_ir_prompt.txt`。

## 開けず見送りの再確認(2026/11/24追加)
PDFが開けなかったもの(ネットのエラー・本文が取れない)は、見送りにせず `inbox/ir/retry.json` に入れ、次の回の最初にもう一度開く。最初の1回のあと最大3回まで(全部で4回)。開けたら通常の確かめに進む。4回でも開けなければ、その日の `inbox/ir/日付.json` の `rejected` に「再確認3回でも開けず、諦めた」と記録して列から外す。本文が開けたうえで確かめに落ちたもの(日付が合わない等)は内容の問題なので再確認しない。`status.json` の `n_retry_waiting` が再確認待ちの件数。

## TDnet新着の見張り(日本の人事係、2026/11/24追加)
`python3 scripts/tdnet_scan.py` が、TDnetの直近2営業日の一覧をぜんぶ見て、相関図にない会社でも「表題が役員人事で、会社名か表題にAI・DX・デジタル・データ・半導体などの語がある(またはCDO・CIO・CTO)」ものだけPDFを開く。本文にもAI系の語があって日付が合うものだけ `inbox/ir/tdnet-scan-日付.json` に保存(`import` は「記録のみ」。人の名前・役職は人事係が本文で確かめてから inbox/moves に足す)。相関図の会社は ir_watch.py の担当なので重ねない。PDFが開けなかったものは上の再確認の列に入れる。

## 日本の提携係向け(2026/11/24追加)
`python3 scripts/tdnet_scan.py --kind alliance` が、TDnetの直近2営業日の一覧から、表題に「提携・協業・業務連携・共同開発」などがある発表だけPDFを開き、本文にAI企業名(OpenAI・Anthropic・Google・Nvidia など)やAI・生成AI・GPU・データセンター・半導体の語があって日付が合うものだけ `inbox/ir/tdnet-scan-alliance-日付.json` に保存する(記録のみ。提携の相手・内容は本文で確かめてから inbox/money に足す)。相関図の会社の資本業務提携・出資は ir_watch.py の担当なので重ねない。開けなかったPDFは上の再確認の列に入り、翌日から最大3回開き直す。再確認待ちの件数は、サイトの「調査エージェント」ページの「今朝のようす」に出る(`python3 scripts/agents_status.py` が `site/agents/status.json` の `retry` に書く)。

## 提携の自動取り込みと、出資・買収の拡張(2026/11/24追加)
`tdnet_scan.py` の `--kind alliance`(業務提携・協業)と `--kind invest`(出資・買収。相関図にない会社も見る。新株予約権の発行は除く)は、次の5つがぜんぶそろったものだけ **自動で `inbox/money/日付-tdnet.json` に足す**(confidence は「開示」、出典は開示のPDF)。1つでも欠けたら足さず、`inbox/ir/tdnet-scan-…json` に「手動」と理由つきで記録するだけ(人が本文を読んで確かめる)。
1. PDFが開け、会社名か証券コードが本文にある 2. 本文の日付が一覧の日付と近い 3. 表題から「だれが・だれと」が決まる(「○○との業務提携」「A社とB社の業務提携」「○○の株式取得」など) 4. 相手の名前が本文にも出てくる 5. 本文にAI企業名(OpenAI など)が1つ以上、またはAI系の語(AI・生成AI・GPU・データセンター・半導体など)が2回以上ある
- alliance は出資・買収の表題を扱わない(invest の担当)。資本業務提携は出資の線(kind「出資」)、業務提携・協業は kind「提携」で足す。
- 試験(直近3営業日・414件): invest は17件のうち本文で確かめたものを自動で1件(ワコムのMBOの公開買付け)足せる形にした。提携は該当1件(表題が長く相手が決まらず、手動のまま)。
- 取り込みは今までどおり merge_inbox.py(毎朝9:13)。足すだけで、消さない。


## 提携の相手を本文から読む(2026/11/24追加)
`tdnet_scan.py --kind alliance` は、表題から相手が決まらないとき、本文の「N．提携先(相手先)の概要」の欄の「(1)名称」から相手を読む。
- 表題と本文の両方で相手が読めて食い違うときは決めない(手動)。どちらか一方だけなら、会社名の形が整っているときだけ使う
- 表題に「解消・終了・延長・継続・日程・子会社・進捗・販売提携」などがあるものは、新しいつながりではないので決めない
- 「の…」で始まる・かっこや「取得」を含む・長すぎる名前は会社名として使わない(試験で、表題の読み違い「のアパレル向け機能性繊維」「子会社と日本ビットコイン産業」などが見つかったため)
- 出す側の会社の名前は、TDnetの一覧の略称(「Ｇ－イオレ」)ではなく、本文の先頭の「会社名」から読む(略称と先頭2文字が合わないときは使わない)
- 本文の証券コードは「コード：2334」の書き方にも対応
- 手動に回したものは、`inbox/ir/tdnet-scan-…json` の `import` に理由が入る
- 精度の試験: `python3 scripts/test_tdnet_body.py [-v]`。実際の提携34件(2026/10/28〜11/20)で、正解12件は12件とも当たり、決めてはいけない・迷う22件で誤り0件。誤りが1件でもあれば失敗する

## HKEX(香港)の出資・買収・提携を全社ぶん見る(2026/11/24追加)
`python3 scripts/hkex_scan.py`(`--dry`で書き込まない)。**ir_watch.py の最後に自動で動く**ので、毎朝の引き抜き調査(ir_watch.py を動かす定期タスク)の変更は要らない。
- 一覧は `lcisehk1relsde_1.json` と `_2.json`(約1日ぶん×2。`hkexnews.hk` は許可済み。`www1.hkexnews.hk`(過去の検索ページ)は許可外で開けない)。相関図の会社でなくても見る
- 表題と分類に、acquisition・investment・subscription・joint venture・cooperation・strategic などがあるものだけPDFを開く。処分(disposal)・リース・社債・配当・自社株買いなどは扱わない(向きが逆、または関係ない)
- 自動で `inbox/money/日付-hkex.json` に足す条件(1つでも欠けたら記録だけ、理由つき): ①本文に証券コード ②本文の日付が一覧の前後7日 ③表題から相手が決まる(「INVESTMENT IN ○○」「ACQUISITION OF …… IN ○○」「COOPERATION AGREEMENT WITH ○○」など。「Target Company」のままのものは決めない) ④相手の名前が本文にも出る ⑤本文にAI企業名が1つ以上、またはAI系の語(AI・GPU・data centre・semiconductor など)が3回以上 ⑥出す側の名前が決まる(相関図の会社は相関図の名前、そうでなければ本文の先頭から)。複数社の共同発表は決めない
- ファンドを通じた間接の出資は、説明文にその旨を書く(例: 知乎のDeepSeekへの出資)
- 開けなかったPDFは inbox/ir/retry.json に入り、翌日から最大3回開き直す(開き直したあとは ir_watch.py の通常の確かめ=記録のみ)
- 表題が相手を「Target Company」とだけ書いているとき(2026/11/24追加): 本文の定義(「“Target Company” (名前)」の表、または「名前 (the “Target Company”)」)から相手の名前を読む。呼び名が本文に3回以上出る・定義が1つに決まる・名前が会社名らしい(Co.・Ltd・Technology などを含む)、のすべてを満たすときだけ。1つでも欠けたら手動のまま。足したときの説明に「相手の名前は本文の定義から読んだ(英訳名)」と書く。覚書(MOU)・Possible の表題には「覚書の段階で、実行は未確定」と書く
- 精度の試験: `python3 scripts/test_hkex_scan.py [-v]`。表題15件と実際の発表13件で、誤り0件(自動で足せたのは、2026/11/24に「ZCLOUD→Shenzhen Yingshuo Cloud Technology(出資の覚書)」を加えた3件。もとの2件は、2026/11/23〜24の分で「知乎→DeepSeek(出資)」と「Huisheng→Shanghai Jingguan Intelligent Technology(買収)」の2件)。日本語の説明文は、表題・本文は英語のまま
- 記録: `inbox/ir/hkex-scan-日付.json`(items=本文で確かめたもの、skipped=AIに関係なかったもの)
- シンガポール(SGX)は今までどおり読めない
