# アジア・オセアニアの会社を調べる(kigyo-asiapac)

サイト: https://kigyo-asiapac.yuma-takeshita.workers.dev

## しくみ(2026年11月18日に調べた)
- 台湾・オーストラリア(約558万社)は、Worker に置いた**ファイル**(約5,600個)に入っている。データベースではない
  - `/c/meta.json` 件数、`/c/{番号}.json` 会社ごとの情報、`/n/hot.json` と `/n/{番号}.json` 検索用
- シンガポール(624,977社、2026年11月18日追加)は、D1 のデータベース「kigyo-sg」の表 `f` に、**同じ形のファイルの中身を1行ずつ**入れてある(1,405行)
  - こうしたのは、この作業環境からは Cloudflare にファイルを送れなかったため(送るときの合言葉が上書きされる)
  - 1行に多くの会社をまとめているので、無料プランの1日の書き込み上限(10万行)にかからない
- `worker.js` が、今のファイルとシンガポールのデータベースの両方を探して、結果をまぜて出す

## ファイル
- `worker.js` 今動いているプログラム(シンガポール入り)
- `worker_before_sg.js` シンガポールを足す前のプログラム(2026/11/17 版、PCから wrangler で出したもの)
- `add_sg_patch.py` 前のプログラムにシンガポールを足した変更
- `deploy_worker.py` プログラムだけを入れ替える(ファイルのデータは残す)。`--rollback <版の番号>` で前の版に戻せる
  - シンガポールを足す前の版: `fb388a9a-b4db-4eee-b3a4-187a0d39476c`

## 注意
- PC の古い元ファイルから `wrangler deploy` すると、シンガポールの部分が消える。PC から出すときは、先に `add_sg_patch.py` と同じ変更を元ファイルに入れる
- シンガポールのデータを作り直す手順は `tools/kigyo-sg/README.md`
